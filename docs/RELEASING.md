# Releasing

Distribution is via **GitHub Releases only** (no PyPI/registry publishing).

1. Make sure `main` is green (CI, `python3 -m pytest tests -q`).
2. Update `CHANGELOG.md`: move `[Unreleased]` entries under a new `## [X.Y.Z] - YYYY-MM-DD` heading and update the compare links at the bottom.
3. Bump the version in `pyproject.toml` (and any version constant) and commit: `chore: release vX.Y.Z`.
4. Tag and push: `git tag -a vX.Y.Z -m "vX.Y.Z" && git push origin main vX.Y.Z`.
5. Create the GitHub Release from the tag (`gh release create vX.Y.Z --title vX.Y.Z --notes-file <notes>`); the notes are the CHANGELOG section for that version plus any upgrade/security warnings. Mark pre-1.0 releases as such if appropriate.
6. Attach artifacts if the release workflow does not (source archive is generated by GitHub).
7. Verify: fresh clone of the tag, quickstart from the README, tests pass.

Security fixes: release a patch version and publish a GitHub security advisory.
